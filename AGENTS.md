# VTT Sonho Jovem

- Leia `documentacao/04-contexto-do-projeto.md` antes de alterar o projeto.
- Use pnpm no workspace e execute os comandos do projeto no Ubuntu (WSL).
- Trabalhe em modo mentoria. Explique em português o que mudou, por que a abordagem foi escolhida e como verificar o resultado. Registre decisões e validações em `documentacao/`.
- Para novas entregas, crie uma branch temática a partir de `main` atualizada. Use nomes como `feat/tokens-e-fichas-de-jogadores`, `fix/descricao` ou `docs/descricao` e commits Conventional Commits.
- Publique a branch em `origin` e abra um Pull Request em rascunho para `main` assim que houver alterações revisáveis. Esses passos fazem parte do fluxo autorizado pelo usuário; não faça novas entregas diretamente em `main`.
- Continue atualizando a branch e o PR durante a entrega. Descreva o comportamento implementado, as validações e o que falta; mantenha o título e a descrição coerentes com o conteúdo final. Faça merge somente quando o usuário solicitar explicitamente.
